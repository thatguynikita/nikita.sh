# What 404.html is

The custom error page, served at whatever broken URL a visitor actually
hits. It's fully hand-authored with zero `GENERATED:*` blocks — see
`CLAUDE.md`/[UPDATE-GUIDE.md](UPDATE-GUIDE.md) — so `content/site-data.mjs`
and `scripts/build.mjs` never touch it. Like `cv.html`, it wears the
terminal chrome for continuity but has no command interactivity of its
own; the only live behavior is the EN/RU toggle.

## Structure

- A fake two-line shell session — `ls <path>` followed by
  `ls: <path>: No such file or directory` — showing the actual path the
  visitor requested, via `getRequestedPath()` below.
- The cat illustration (`.cat-frame` / `#catPhoto`), theme-reactive
  duotone via a masked overlay — the exact mechanic is documented in
  `CLAUDE.md`'s Theming section, since it's the more complex (masked,
  not-in-an-opaque-frame) variant of `cv.html`'s avatar treatment.
- One bilingual message line, and the standard footer.

## Path detection

`getRequestedPath()` reads `decodeURIComponent(location.pathname)`,
strips all leading slashes, and falls back to `"unknown-page"` if that
leaves nothing (root, or an undecodable path). The result is written via
`textContent` (not HTML) into both the `ls` line and its error line, so
there's no injection risk from an arbitrary requested path.

## Why asset paths are root-absolute

`/theme.css`, `/theme.js`, `/cv.html`, and the favicon `<link>`s all use
root-absolute paths rather than relative ones — this page can be served
at any broken URL, and a relative path resolves against whatever the
browser's address bar shows, not this file's real location. Full
reasoning in `CLAUDE.md`'s Theming section; don't change these back to
relative paths.
